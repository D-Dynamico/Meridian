**Decisions**
- Only a UTM source is measured in place (D15). The old rule, "projected and in metres",
  would have measured Web Mercator directly at +22.3 percent area error.
- Missing `.prj` stores `EPSG:4326` with `crs_assumed: true` instead of null (D10 revised).
  The brief needs every feature to report a CRS; the flag is what carries the warning.
- Per-feature `source_crs` column, file `crs` becomes `MIXED` when layers disagree. A zip
  can hold several shapefiles with different `.prj` files.
- `make_valid` output is filtered to polygon parts. Nothing left means "degenerate
  polygon", never a length.
- Beyond 84°N or 80°S, UTM does not exist: the geodesic value is reported, with a note and
  a null `measurement_crs`.
- Notes joined with `"; "` in a fixed order (D16). Every result carries every field.
- Startup marks orphaned `PENDING` and `PROCESSING` files `FAILED` (D17).
- Hidden slashless route aliases (D18). The 307 problem was overstated in the review:
  httpx and requests both follow it and resend the body. Kept anyway to save a round trip.
- `feature_index` column (D19), for readability only. SQLModel quotes `index` fine.
- Stage 1 upload schedules no task. Files stay `PENDING` until the Stage 4 processor.
- Follow-up from the user's review: explicit `measurement_method` (`projected` or
  `geodesic`) on every measured feature, and `geodesic_value` is never null on a measured
  feature, including the polar fallback (D22). Consumers should not have to infer the
  method from a null `measurement_crs`.
- Settled: 50 MB upload limit (D20); 409 for measurements while `PENDING`, `PROCESSING` or
  `FAILED`, with the failure reason in `detail` (D21); Python 3.12 on `python:3.12-slim`
  (D23).

**Surprises**
- The planned 0.1 percent projected against geodesic tolerance would have failed a correct
  implementation. It only held because the Jaipur fixture sits 0.8° from its zone's central
  meridian. Measured area gaps: Jaipur -0.064%, central meridian at the equator -0.080%,
  Bengaluru +0.116%, zone edge at the equator +0.195%. Max length gap 0.098%. New
  tolerances: 0.25% area, 0.15% length.
- A 1 km square drawn in UTM coordinates measures exactly 1,000,000 m2 in that zone and
  tests nothing. Fixtures must be built with `Geod.fwd`.
- Hemisphere bugs do not show in areas: 56°N and 56°S squares measure identically. Tests
  must assert the EPSG code.
- `Geod.geometry_area_perimeter` returns negative area for clockwise rings, which is what
  every Shapefile exterior is.
- `make_valid` on a zero-area sliver returned a MultiLineString, which a naive dispatcher
  would have measured as a length.
- pyogrio warns (it is not silent) when a multi-layer KML is read without naming a layer.
  It is still easy to miss in a background task's log, so the convention stands.
- LIBKML adds about 11 mostly-null system columns to KML properties. Left as an open
  decision for Stage 2.
- Git on this machine converts LF to CRLF on checkout (`core.autocrlf`). Harmless for
  docs; consider a `.gitattributes` in Stage 1 so the Dockerfile and shell files stay LF.

- **The planned size check could not work where the docs put it.** FastAPI reads and
  parses the whole multipart body (`fastapi/routing.py`, `await request.form()`) before
  any dependency or handler runs, so a `Content-Length` check in the route fires only
  after a 2 GB upload has been fully received. Moved to ASGI middleware. It must raise
  `HTTPException`: FastAPI re-raises that from body parsing, but turns any other
  exception into a generic 400 "There was an error parsing the body".
- **Three tests that could not fail**, each found by mutation:
  - The `.gitattributes` test passed with the `*.shp` rule deleted, because Windows sets
    `core.ignorecase` and `*.SHP` matched instead. The test now forces it off to see
    what Linux sees.
  - Unwiring the size middleware left every test green: the route's own size check also
    returns 413. Middleware tests now upload an unsupported extension, so a 413 can only
    come from the middleware (the route would say 415).
  - The filename test used `C:\...\survey.kml`, but python-multipart already strips
    drive-letter paths before the route sees them, so the route's base-name step was
    never exercised. Relative and POSIX paths do arrive intact; the test uses those now.
- The ad hoc mutation script corrupted `app/api/files.py`: `read_text()` defaults to
  cp1252 on Windows, and writing back as UTF-8 double-encoded every `§`. Caught by a
  non-ASCII grep, repaired, script fixed to pass `encoding="utf-8"`. Any file tooling on
  this machine needs an explicit encoding.
- A UTC fix that was not needed. I added a validator to re-attach UTC to timestamps,
  assuming SQLite returns naive datetimes. The mutation check removing it stayed green:
  SQLModel 0.0.47 maps `datetime` fields to its own `UTCDateTime` type, which already
  returns aware UTC values. Validator removed. The test that the API says `...Z` stays,
  and forcing a plain SQLAlchemy `DateTime` column turns it red, so it guards against a
  SQLModel upgrade changing this.
- Starlette 1.7 deprecates `httpx` for its TestClient in favour of `httpx2`, a drop-in
  swap.
- The GitHub repo `D-Dynamico/Meridian` already existed and was **public** (anonymous API
  returned 200). The push was held until the user made it private (anonymous API then
  returned 404), then Stage 0 and Stage 1 were pushed together (`7d22006..31ffbb0`).
  It must be made public again at submission (`WORKFLOWS.md` §14).
